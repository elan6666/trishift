# AGENTS.md

Project-level instructions for agents working in the TriShift code repository.

## Manuscript Editing Order

- When paper text, captions, figure references, or supplement explanations need
  to change, edit in this order:
  1. Chinese manuscript;
  2. English manuscript;
  3. Supplement.
- Treat the Chinese manuscript as the content source of truth for claim order,
  terminology, figure references, caveats, and result interpretation.
- After the Chinese structure is settled, mirror the same content decisions into
  the English manuscript; then update the supplement for detailed definitions,
  provenance, extra metrics, and figure-specific notes.
- Use the Bioinformatics article format as the submission/formatting standard.
- Use the scPRAM paper structure as the main manuscript-organization reference,
  especially the structured abstract, Introduction funnel, Methods organization,
  Results section sequencing, and figure-linked result paragraphs.
- Use other reference papers only as secondary style or technical-context aids;
  do not let them override the Bioinformatics/scPRAM ordering rule.

## Results Writing Style

- For Results revisions, default to the scPRAM paragraph rhythm while keeping
  the prose tighter and more Bioinformatics-like than scPRAM itself:
  1. open with why the evaluated question matters;
  2. state the exact split, held-out setting, or experimental design;
  3. explain what the metric measures and its direction when first introduced;
  4. compare TriShift with the strongest or most relevant baselines;
  5. close by connecting the observation to the method advantage or biological
     implication, without drifting into broad Discussion claims.
- Include a small number of quantitative anchors in each Results subsection.
  Prefer 1-2 numbers per main claim, always tied to dataset, metric, baseline
  and setting. Do not turn Results into a panel-by-panel table in prose.
- Results text must analyze and explain the observed outcome, not merely state
  where metrics appear. After reporting a key metric, add a concise explanation
  of what the result shows about the model behavior, biological signal,
  component contribution or evaluation boundary.
- Use scPRAM-like transitions when they help the evidence flow, such as
  "To demonstrate", "To substantiate", "To provide a more intuitive view",
  "First", "Next", "Furthermore", "Finally", "In contrast", "This indicates"
  and "This suggests". Keep them concise and avoid repeating the same transition
  mechanically.
- When borrowing this style, preserve TriShift-specific caveats: distinguish
  held-out-control genetic perturbation tasks from PBMC target-domain-control
  transfer, avoid unsupported broad cytokine/protein-prior claims, and keep OT
  references framed as prediction origins rather than true cell-wise matches.

## Server Execution

- Use the saved `server-access-yilangliu` workflow for remote work.
- Start remote commands from `/data/yilangliu/trishift` unless the user names another path.
- Never write server credentials into this repository, Byte OS files, shell scripts, notebooks, logs, or chat output.
- Before overwriting remote files, preserve the remote dirty state with a status snapshot and diff patch.

## Editing Boundaries

- Keep figure workflow changes focused on notebooks, notebook helpers, docs, and provenance files.
- Do not rerun expensive training or baseline experiments unless a notebook execution fails because a required artifact is missing.
- Do not stage or commit changes unless the user explicitly asks.
